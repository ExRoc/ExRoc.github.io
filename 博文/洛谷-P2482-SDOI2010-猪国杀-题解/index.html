洛谷 P2482 [SDOI2010] 猪国杀 题解

题目链接

P2482 [SDOI2010] 猪国杀

思路

实体类确定

本题非常适合使用面向对象思路编写代码，根据题意可先确定以下几个对象与负责模块：

  • Card：枚举类，表示单张卡牌
  • Deck：牌堆类，用于控制摸牌
  • Role：枚举类，表示玩家身份
  • Player：玩家基类，主要负责以下逻辑：
    • 摸牌阶段摸牌、杀死反猪奖励摸牌、主杀忠惩罚弃牌
    • 角色的出牌决策，配合玩家身份确定
    • 确定打出、响应【杀】【决斗】【南蛮】【万箭】【无懈】等卡牌
    • 吃【桃】与濒死自救
  • ZhuZhu、ZhongZhu、FanZhu：Player 的三个子类，根据当前玩家与目标角色表现出来的身份进行决策，如：忠不对主决斗、对什么角色献殷勤、表敌意、决斗等
  • ZhuGuoSha：进行游戏流程的控制，负责回合流转、伤害结算、AOE、决斗无懈询问与角色响应的询问，游戏胜负判断与结果输出

辅助类型

  • Action：一次出牌动作类，记录当前出牌与出牌目标列表，由 ZhuGuoSha 流程控制类询问玩家，玩家根据自身手牌、身份判断做出动作，将 Action 对象返回，ZhuGuoSha 类再根据玩家动作执行后续流程

  • Intent：枚举类，表示玩家意向，献殷勤或表敌意

  • PlayerFactory：玩家实体工厂，使用工厂模式创建玩家对象，创建后返回Player基类指针，用于实现多态

Intent 意向枚举类

区分献殷勤与表敌意，主要用于根据意向判断是否需要对目标玩家出【无懈】

Action 动作类

表示玩家的一个出牌动作，由 ZhuGuoSha 流程类询问玩家时产生，流程类再根据动作执行后续操作：

  • empty() 得到类数据成员 noAction 的引用，表示一个玩家不出牌的动作，card 类型为 optional<Card>，当 !card.has_value() 表示玩家不出牌，不出牌时 targets 列表为空
  • playACard 表示玩家将对 target 单一目标打出 card 牌，playAnAOE 表示玩家将对 targets 多个目标打出 card 牌，均为类函数成员，方便创建 Action 对象
  • isPlay() 用于判断玩家是否出牌，不暴露 !card.has_value() 的内部逻辑，play(card) 用于判断是否打出 card 牌，符合自然语言习惯
  • getTarget() 与 getTargets() 仅为方便获取单体、群体目标分别设置的函数，getTarget() 实际为 targets[0]

Player 玩家类

与 ZhuGuoSha 同样重要的类，承担玩家出牌策略，以下仅展示核心代码声明及相关设计逻辑，如玩家血量、是否装备【连弩】、本回合是否出【杀】等基础逻辑不展示：

  • 玩家通过 innerRole 与 outerRole 区分实际身份与表现身份
    • innerRole 仅可能为 ZHU_ZHU、ZHONG_ZHU、FAN_ZHU
    • 使用 is(Role role) 方法判断实际身份，玩家死亡奖励、惩罚、判断游戏是否达成胜利条件时必须使用该方法
    • 主猪的初始 outerRole 是 ZHU_ZHU，其它玩家初始值为 UNKNOWN，如果出现南蛮、万箭误伤主猪且未跳身份，将导致 outerRole 被标记为 LEI_FAN_ZHU，跳忠后标记为 ZHONG_ZHU，跳反后标记为 FAN_ZHU
    • 使用 isLike(Role role) 方法判断表现身份，主要用于判断是否应该对对方献殷勤、表敌意
    • 代码中使用 is(role) 或者 isLike(role) 符合自然语言习惯
  • shouldBeFriendlyTo 与 shouldBeHostileTo 用于判断是否应该对 target 玩家献殷勤、表敌意，主要根据当前玩家实际身份与 target 的表现身份确定，所以在基类中只能是虚函数，由子类确定意向，以下给出对应身份的意向：
    • 主猪：对主猪、忠猪献殷勤，对反猪、类反猪表敌意
    • 忠猪：对主猪、忠猪献殷勤，对反猪表敌意
    • 反猪：对反猪献殷勤，对主猪、忠猪表敌意
    • 对表现身份为 UNKNOWN 的玩家不献殷勤也不表敌意
  • chooseJueDouTarget 用于确定决斗对象，主猪与忠猪的逻辑一致：对距离自己最近的需要表敌意的玩家决斗，将该逻辑写于 Player 基类，反猪只会选择主猪决斗，将该逻辑写于 FanZhu 派生类内
  • takeAction 为当前玩家出牌阶段，选择“使用最靠左的能够使用的牌”逻辑的实现，返回一个 Action 表示玩家即将执行的动作，以下为出牌阶段可出牌逻辑：
    • 【桃】：
      • 条件：非满血
      • 目标：当前玩家
    • 【杀】：
      • 条件：（本回合未使用【杀】 或者 曾装备【连弩】）且（可对下一位玩家表敌意）
      • 目标：下一位玩家
    • 【决斗】：
      • 条件：存在可表敌意的玩家（未跳身份且非类反玩家不可表敌意）
      • 目标：由 chooseJueDouTarget 决定
    • 【南猪入侵】【万箭齐发】：
      • 条件：无
      • 目标：所有其它玩家，从当前玩家开始逆时针方向
    • 【猪哥连弩】：
      • 条件：无
      • 目标：当前玩家
  • respondToJueDou：对【决斗】的响应，主猪与反猪可直接出【杀】，该逻辑写于 Player 基类，忠猪的决斗对象为主猪时不会出【杀】，其它情况都直接出【杀】，该逻辑写于 ZhongZhu 派生类内
  • respondToWuXieKeJi：对【无懈可击】的响应，若手上有【无懈】：
    • 若 intent 为 XIAN_YIN_QIN 且当前玩家可对 target 献殷勤，则出【无懈】，否则不出
    • 若 intent 为 BIAO_DI_YI 且当前玩家可对 target 表敌意，则出【无懈】，否则不出
  • onDamaged：仅主猪需要，受到来自 isLike(UNKNOWN) 玩家的南蛮、万箭伤害时，需将伤害来源标记为 LEI_FAN_ZHU，基类默认逻辑为空
  • onKill：死亡结算，任何玩家杀死反猪从牌堆摸三张牌（基类默认逻辑），主猪杀死忠猪弃所有牌（包括连弩）
  • ~Player()：基类需提供默认析构函数，防止派生类对象销毁时出现未定义行为

PlayerFactory 玩家工厂类

使用工厂设计模式创建玩家，创建后返回Player基类指针，用于实现多态：

  • 仅需注意返回类型为 unique_ptr<Player>，是 Player 类型的独占智能指针，仅在游戏开始时创建，游戏结束后自动销毁
  • 玩家创建完成后交给 ZhuGuoSha 流程控制类作为数据成员，由于在游戏过程中不再涉及玩家对象的创建与销毁，函数内部实现均使用智能指针的 get() 方法获取裸指针进行操作，不存在内存泄漏问题

ZhuGuoSha 流程控制类

最重要的类，以下仅展示核心代码及相关设计逻辑：

  • players 为场上玩家列表，deck 为牌堆
  • main 函数通过构造函数创建流程控制类，调用 run() 进行游戏，printFinalState() 按题目格式要求输出游戏终局
  • run() 函数内部从主猪开始，按逆时针顺序依次对存活玩家执行 runPlayPhase(Player* player)（即单个玩家的摸牌、出牌阶段）
  • runPlayPhase 函数内部在玩家摸牌后进行出牌询问，只要【当前玩家存活】且【游戏胜利条件未确定】且【玩家选择了出牌】，就需要继续询问玩家是否出牌，注意玩家可能在出牌阶段由于决斗死亡，死亡后不可继续出牌
  • bool playCard(Player* player) 即对当前玩家询问出一张牌的执行流程，返回 bool 值表示是否出牌了，若玩家出牌了且满足以上条件，runPlayPhase 就要继续询问玩家的下一张出牌
  • 玩家出牌后若需要其它玩家响应，则执行对应的 resolveXXX
  • resolveSha：若 target 出【闪】则无事，未出【闪】认为 source 对 target 出【杀】造成一点伤害，调用 dealDamage(source, target, Card::SHA) 结算伤害
  • resolveJueDou：
    • 先调用 resolveWuXieKeJi(source, target, Intent::XIAN_YIN_QIN) 询问【决斗】是否被无懈，第一次无懈的 intent 必然是对 target 献殷勤（【南蛮】【万箭】相同）
    • 若被无懈则结束【决斗】结算
    • 否则从 target 开始与 source 轮流出【杀】，没有【杀】的玩家受到来自对方的一点伤害，调用 dealDamage(winner, loser, Card::JUE_DOU) 结算伤害
  • resolveAOE：【南蛮】【万箭】的 targets 为除当前玩家外逆时针方向转一圈的其它玩家
    • 每个玩家都要先从出 AOE 的玩家开始询问【无懈】
    • 若被无懈，则下一个 target 玩家继续结算
    • 若未被无懈，则询问 target 玩家是否出【杀】【闪】响应，出牌响应则下一个玩家继续结算
    • 否则受到来自 source 玩家的伤害，调用 dealDamage(source, target, sourceCard) 结算伤害
    • 注意可能在 AOE 结算到某一位 target 玩家死亡后，达成游戏胜利条件，则后续玩家不再结算
  • resolveWuXieKeJi：这是一次递归的无懈询问，无懈的锦囊可能是【决斗】【南蛮】【万箭】，也可能是【无懈】
    • 打出锦囊的玩家即 source，被使用锦囊的玩家即 target，从 source 开始逆时针询问一圈，是否有对 target 意向为 intent（献殷勤 / 表敌意）的玩家
      • 若无人出牌，则当前锦囊生效
      • 若有 intent 意向且手牌有【无懈】的玩家则出无懈，结束本轮询问，认为当前锦囊即将失效
        • 递归询问是否有对当前 target 有相反意向的玩家出【无懈】
          • 若有则刚出的【无懈】被抵消 → 即当前锦囊生效
          • 若无则本次【无懈】生效 → 即当前锦囊失效
  • dealDamage：target 生命值 - 1，若出现南蛮、万箭误伤主猪，需标记类反猪
    • target 存活则继续游戏
    • target 濒死询问是否对自己出桃，出桃则继续游戏，否则 target 死亡
    • 死亡后先进行游戏胜利条件判断，若达成条件则直接结束游戏
    • 若未达成条件，进行死亡奖励、惩罚，杀死反猪 source 摸三张牌，杀死忠猪的主猪需丢弃所有牌（包括装备区的连弩）
